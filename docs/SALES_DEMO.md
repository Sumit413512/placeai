# 12-Minute Client Demo

## 1. Open with the buyer problem — 60 seconds

Show the public homepage and submit a demo request to prove the sales lead flow. Position PlaceAI as the institution-controlled operating layer replacing spreadsheets, message groups, manually shared résumés and disconnected reports.

## 2. Institution/TPO workspace — 4 minutes

Sign in as `tpo@northstar.example.com` in the demo seed.

Show:

1. Placement command centre metrics.
2. Student records and verification.
3. Recruiter provisioning.
4. Campus jobs: explain pending approval.
5. Approve a job and create a drive.
6. Configure CGPA, branch and batch eligibility.
7. Applications/outcomes view.
8. Bulk CSV onboarding and the institution audit log.

Buyer value: governance, consistency and reporting.

## 3. Student workspace — 3 minutes

Sign in as `student@northstar.example.com`.

Show profile completion, opportunities, campus drives, eligibility check, applications, résumé and AI preparation.

Buyer value: fewer repetitive placement-office questions and clearer student readiness.

## 4. Recruiter workspace — 3 minutes

Sign in as `recruiter@acme.example.com`.

Show job listings, applicants, status pipeline, candidate visibility and optional AI ranking.

Explicitly point out that unrelated student records are not an open directory by default.

Buyer value: recruiter usability without giving away the institution's entire student database.

## 5. Close — 60 seconds

Propose a pilot with one graduating batch and a limited recruiter cohort. Define success metrics before rollout: administrative hours saved, student completion rate, application turnaround, recruiter response rate and outcome reporting time.
