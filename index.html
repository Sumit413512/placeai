Placement-software benchmark

Baseline features are necessary. Depth is the differentiator.

POD.ai publicly highlights automation, notifications, real-time tracking, standardized candidate information, analytics, communication, scheduling and job-fair support. PlaceAI retains those core categories while extending deeper into governance, verification, evidence, policies, AI readiness and institution-controlled workflows.

PlaceAI approachBeyond workflow digitization.

Instead of copying another platform screen-for-screen, PlaceAI combines placement execution with trust controls, readiness intelligence and institution governance.

Communication → auditable operationsAnnouncements plus recruiter threads, attachments, notifications and activity history.
Tracking → configurable pipelineEligibility, application stages, custom drive rounds, interviews, evaluation and offers.
Reports → decision intelligenceDepartment placement, CTC, conversion, employer participation and unplaced segmentation.
Resume standardization → readinessResume parsing, profile evidence, skills, readiness scoring and preparation recommendations.
Recruiter access → company trustProvisioning plus evidence review, CIN/GSTIN fields, verification confidence and institution approval.
Scheduling → execution controlsCalendar, interviews, QR attendance, attendance windows, outcomes and offer joining dates.
Automation → policy enforcementExplicit placement rules and explainable restrictions rather than hidden spreadsheet logic.
AI → human-reviewed assistanceMatching, readiness and summaries assist people; final placement decisions remain human-controlled.
Production trust

Candidate data is not an open directory.

PlaceAI is designed around controlled recruiter access, tenant-aware business rules and server-side role authorization. Production storage and sessions are persistent, while high-risk defaults fail closed.

Supabase security advisor: no active security lints in the latest connected audit.
Argon2 passwordsStrong password policy for new and reset credentials.
Rotating refresh sessionsDatabase-backed refresh session rotation and revocation.
Cross-tenant validationInstitution ownership checks across drives, interviews and communications.
Hardened uploadsMagic-signature and package validation for supported files.
Durable throttlingDatabase-backed login, reset, signup and public-demo abuse controls.
Controlled data API postureApplication access remains through the backend rather than a public table surface.
Production file persistenceUploaded bytes are persisted in PostgreSQL for serverless production.
Permanent release gatesCI, Bandit, pip-audit, manifest and external smoke workflows.
